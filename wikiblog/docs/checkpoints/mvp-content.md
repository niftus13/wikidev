# 체크포인트 요구사항: MVP 콘텐츠 기능 마무리 — 발행 취소 · 이미지 첨부(DB) · 플랫폼 카테고리

- 작성: 2026-11-19
- 상태: **확정** (2026-11-19 사용자 결정. 이 체크포인트에는 미결 질문이 없다)
- 규모 원칙: 서비스는 **MVP 규모로 유지**한다. 외부 저장소, 별도 관리 화면, 배치 작업을 새로 늘리지 않는다.

## 1. 결정 (2026-11-19)

| 항목 | 결정 |
| --- | --- |
| 발행 취소 | **도입한다.** 페이지 단위로 하고, 하위 발행 페이지도 같은 트랜잭션에서 함께 발행 취소한다(삭제가 하위까지 함께 지우는 것과 같은 규칙). 책은 생성 즉시 공개 정책을 유지하고, 책 단위 발행 취소는 없다. |
| 삭제 복구 | **보류를 유지한다.** 논리 삭제라 데이터는 남는다. 복구가 필요하면 운영자가 런북의 수동 절차(SQL)로 처리한다. 복구 API와 UI는 만들지 않는다. |
| 이미지 첨부 | **S3 없이 MySQL에 저장한다.** `images` 테이블에 UUID 키와 바이너리를 둔다. 외부 이미지 주소는 허용하지 않는다. |
| 플랫폼 카테고리 | **관리 API·운영자 인증은 만들지 않는다.** 기본 분류를 마이그레이션 시드로 넣고, 바꿀 때도 새 마이그레이션으로 한다. |
| 신고·운영자 대응 | 신고 기능은 만들지 않는다. 운영자는 사용자를 비활성화(`users.status`)해 콘텐츠를 숨긴다. 이미 있는 동작이고, 절차는 런북에 적는다. |
| 책 개수 제한, 계정 기준 로그인 제한 | 도입하지 않는다. 남용 방지는 IP 기준 요청 제한과 이미지 용량 제한으로 한다. |
| 브랜드 색 | 헤더 마크 색 `#2663ce`로 통일했다(`--accent`, hover `#1d50a8`). 2026-11-19 반영 완료. |

## 2. 범위

### A. 발행 취소 (`backend-engineer` + `publishing-workflow`, 화면은 `frontend-engineer`)

| ID | 요구사항 |
| --- | --- |
| A-1 | `POST /api/v1/pages/{pageId}/unpublish`를 추가한다. 소유자만 가능하고 CSRF가 필요하다. 다른 사용자의 페이지는 404이다. 발행되지 않은 페이지는 멱등하게 200을 반환한다. 발행된 하위 페이지도 같은 트랜잭션에서 `published_version_id = NULL`로 바꾼다. |
| A-2 | 초안과 이력은 그대로 둔다. 다시 발행하면 현재 초안 revision으로 발행한다. |
| A-3 | 발행 취소 직후 공개 조회·공개 목차·검색·분류 필터에서 바로 빠진다. CDN과 캐시가 없으므로 무효화할 것은 없다. 공간 화면 책 목록은 책 단위라 영향이 없다. |
| A-4 | 화면: 페이지 목록·편집 화면에 "발행 취소" 버튼을 둔다. 확인 대화에서 하위 발행 페이지 수를 안내한다. 성공하면 발행 상태를 갱신한다. |
| A-5 | 통합 테스트를 쓴다. 다룰 경우는 다음과 같다. |
| | 발행 취소 후 공개 페이지 404, 목차·검색에서 제외, 하위 페이지도 함께 취소, 다른 사용자 404, CSRF 없으면 403, 재발행 가능. |

### B. 이미지 첨부 — MySQL 저장 (`backend-engineer` + `cache-and-db`, 화면은 `frontend-engineer`)

| ID | 요구사항 |
| --- | --- |
| B-1 | 새 마이그레이션으로 `images` 테이블을 만든다. 컬럼은 `id` UUID, `space_id`, `content_type`, `byte_size`, `sha256`, `data` MEDIUMBLOB, `created_at`이다. |
| B-2 | 업로드는 `POST /api/v1/me/images`이다. 로그인과 CSRF가 필요하다. |
| | JSON 16KB 제한과 분리하기 위해 이 경로만 `Content-Type: image/*` 원본 바이트를 받는다(raw body). Origin 검사는 유지한다. |
| | 허용 형식: PNG, JPEG, WebP, GIF. **파일 시그니처(매직 바이트)로 확인**하고, 선언한 형식과 실제 형식이 다르면 거부한다. **SVG는 거부한다**(스크립트 실행 위험). |
| | 크기 상한은 2MB, 공간당 총량은 50MB이다(MVP). 넘으면 413이나 409로 응답한다. |
| B-3 | 조회는 `GET /api/v1/images/{uuid}`이다. 공개이고 인증은 필요 없다. UUID는 추측할 수 없는 값이다. |
| | 응답 헤더: 저장한 `Content-Type`, `X-Content-Type-Options: nosniff`, `Cache-Control: public, max-age=31536000, immutable`, `Content-Disposition: inline`. |
| | 없거나, 형식이 잘못됐거나, 소유자가 비활성인 이미지는 404이다. |
| B-4 | Markdown 렌더링(`renderMarkdown`): `img`의 `src`는 **같은 출처의 `/api/v1/images/<uuid>`만** 허용한다. 외부 http/https 이미지는 지금 허용되지만 이제 제거한다. 링크(`a`)의 외부 주소는 그대로 허용한다. |
| B-5 | 편집 화면 이미지 넣기. 상세는 아래 **B-5 화면 설계**를 따른다. |
| B-6 | 정리는 MVP에서 하지 않는다. 페이지를 삭제하거나 본문에서 빠진 이미지(고아 이미지)도 남겨 둔다. 용량 상한으로 늘어나는 양을 제한하고, 정리 작업은 후속으로 둔다. |
| B-7 | 테스트: 형식·시그니처 검증, SVG·위장 파일 거부, 크기·총량 상한, 다른 사용자의 업로드 경로 접근, 조회 헤더, 렌더러가 외부 이미지를 제거하는 단위 테스트. |
| B-8 | 운영 영향을 런북에 적는다. |
| | MySQL 백업(`mysqldump`)과 EBS 용량이 이미지만큼 커진다. 공간당 50MB 상한을 기준으로 디스크를 계획한다. |
| | 업로드 경로가 nginx의 요청 본문 상한보다 크지 않아야 하므로, nginx `client_max_body_size`를 이 경로만 2MB 이상으로 둔다. |

#### B-5 화면 설계 (2026-11-19 확정)

**넣는 방법** (페이지 편집 화면의 본문 입력 칸)
- 툴바의 이미지 버튼(`@lucide/vue` `ImagePlus`, `aria-label`). 숨긴 `<input type="file" accept="image/png,image/jpeg,image/webp,image/gif" multiple>`를 연다.
- 클립보드 붙여넣기(`paste`의 이미지 항목). 글자 붙여넣기는 그대로 둔다.
- 끌어다 놓기(`dragover`/`drop`). 놓을 수 있는 동안에는 칸 테두리를 강조한다.
- 여러 장이면 순서대로 하나씩 올린다.

**업로드 흐름**
1. 브라우저에서 먼저 검사한다(형식 4종, 2MB). 통과하지 못하면 업로드하지 않고 안내한다. 최종 판정은 서버가 매직 바이트로 한다.
2. 커서 위치에 고유 표시를 가진 임시 자리 `![업로드 중: <이름>](uploading:<임시 id>)`를 넣는다.
3. `POST /api/v1/me/images`로 보낸다(원본 바이트, `Content-Type`은 파일 형식, `X-CSRF-Token` 포함).
4. 성공하면 임시 자리를 `![<alt>](/api/v1/images/<uuid>)`로 바꾼다. 실패하면 임시 자리를 지우고 안내한다.
   - 사용자가 그 사이에 임시 자리를 지웠으면 결과를 넣지 않는다.
   - alt 기본값은 파일 이름에서 확장자를 빼고 정리한 값이다. 이름이 없으면 "이미지"를 쓴다.

**상태와 오류**
- 업로드 중에는 버튼에 스피너를 띄우고, `role="status"`로 "이미지 n/m 업로드 중"을 알린다. 저장·발행 버튼은 잠근다.
- 오류 문구: 형식(400/415) "PNG·JPEG·WebP·GIF만", 크기(413) "2MB 이하", 용량(409) "이미지 저장 공간(50MB)을 모두 사용", 401은 기존 입력 보존과 "새 탭에서 로그인", 그 밖은 다시 시도 안내.

**저장과 표시**
- 본문은 기존 초안 저장, revision, 이탈 확인 규칙을 따른다. 저장하지 않은 업로드 이미지는 고아 이미지로 남는다(B-6).
- 미리보기와 공개 화면은 같은 `renderMarkdown`을 쓴다. 내부 주소만 `<img>`로 남기고, `loading="lazy"`·`decoding="async"`를 붙인다.
- `.markdown-body img`는 `max-width: 100%`이다. 스타일은 main.css 클래스로만 넣는다(인라인 금지).

**코드 배치**
- `app/utils/imageUpload.ts`: 순수 함수(검사, alt, 삽입·교체, 오류 문구). 단위 테스트를 둔다.
- `app/composables/useImageUpload.ts`: 요청, 순서 처리, 상태
- `app/components/ImageUploadButton.vue`
- 페이지 편집 화면: 붙여넣기·드롭 연결과 잠금
- Playwright 검증: 버튼·붙여넣기·드롭, 오류, 미리보기, 공개 표시

**하지 않는 것**: 크기 조절·자르기·썸네일, 갤러리와 개별 삭제, 고아 이미지 정리, 퍼센트 진행률.

### C. 플랫폼 카테고리 시드 (`backend-engineer`)

| ID | 요구사항 |
| --- | --- |
| C-1 | 새 마이그레이션으로 최상위 플랫폼 카테고리 6개를 넣는다: 개발, 데이터·AI, 디자인, 비즈니스, 학습·교양, 일상·기타. 고정 UUID를 써서 다시 실행해도 같은 결과가 나오게 한다(멱등). |

| C-3 | 카테고리를 바꿀 때도 새 마이그레이션으로 한다. 이미 적용된 마이그레이션은 수정하지 않는다(체크섬 검증). |

## 4. 수용 기준

- [ ] 발행 취소한 페이지와 하위 페이지가 공개 조회·목차·검색에서 바로 사라지고, 다시 발행할 수 있다.
- [ ] 허용된 이미지만 업로드되고 SVG·위장 파일·상한 초과는 거부된다. 본문에는 내부 이미지 주소만 렌더링된다.
- [ ] 이미지 조회 응답에 `nosniff`와 올바른 `Content-Type`이 있다.
- [ ] 플랫폼 카테고리 6개가 시드되어 책 분류 패널에 나타난다.
- [ ] API 통합 테스트(건너뜀 0)와 웹 테스트·타입 검사·운영 빌드가 통과한다. 브라우저 검증은 Playwright Docker로 한다.
- [ ] README·history·런북 요구사항(운영 배포 문서)에 운영 영향이 기록되어 있다.
